# Audit log integrity
Every audit row gets a chain MAC = HMAC-SHA256(key, prev || id || ts || user || action), written in the same transaction (`db.audit_add`). Key = derived from an encryption-ring key whose id is pinned in `settings.audit_key_kid` (not in the DB's secret material). `GET /api/audit/verify` (admin) reports edited/deleted/injected rows. `POST /api/audit/checkpoint` returns/stores a signed chain head.
**Limits (be honest):** an attacker with the database **and** the key ring can rewrite the whole chain. Detection of that relies on checkpoints stored **off-host**: set `SOC_AUDIT_CHECKPOINT_DIR` to a WORM/remote mount (or ship `audit-checkpoints.jsonl` with `rsync`/syslog to another host on a schedule). Verify a stored checkpoint against the live chain with `security.auditchain.verify_checkpoint`. Rows written before this upgrade are "unchained" (reported, not verified). Direct `INSERT INTO audit` from other code would be flagged as injected — all writers must use `db.audit_add`.
